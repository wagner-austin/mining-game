## WS-021 API Contract (Final)
- `Shop.GetShopCatalog(category?: string, rarity?: string)`
  - Returns: `{ ok: boolean, success: boolean, items: { id: string, name: string, price: number, rarity: string, slot?: string, enhanced?: boolean }[] }`
  - Options: may filter by category (e.g., `cosmetic`) and rarity.
  - Rate limit: 0.2s; `opts.requireProfile = true` not required (view allowed without profile is acceptable), but may be enabled for simplicity.

- `Shop.PurchaseItem(itemId: string, quantity?: number = 1)`
  - Validates item exists and purchasable; cosmetics forced to quantity=1; reject `quantity > 1`.
  - Affordability via `CurrencyService.canAfford`; deduct with `CurrencyService.add(player, "coins", -price)`; grant with `InventoryService:AddItem`.
  - Returns: `{ ok: boolean, success: boolean, purchased: string, quantity: number }` on success, or `{ ok: false, success: false, err, reason }`.
  - Error codes: `INSUFFICIENT_FUNDS`, `ITEM_NOT_FOUND`, `INVALID_INPUT`, `NOT_AVAILABLE`.
  - Rate limit: 0.2s; `opts.requireProfile = true`.

- Feature flags
  - `GameConfig.Features.SHOW_SHOP_TAB` – gates UI/tab visibility.
  - `GameConfig.Features.ENHANCED_COSMETICS_ENABLED` – controls catalog exposure for enhanced items.

## Engineering Standards (Release)

Architecture & DI
- Use ServiceContainer for server dependencies; resolve via `ServiceValidator.get/tryGet(container, name, {methodList?})`.
- RemoteFunctions live under `server/MiningGame/RemoteFns/*.rf.lua` and export a factory `(container) -> {specs}`.
- Validate inputs, set `opts = { requireProfile?, rateLimitSec?, debugOnly? }`, and return normalized `{ ok, success, ... }`.
- Emit events via `EventBus.global()` with typed contracts under `shared/MiningGame/EventContracts.lua`.
- Guard Roblox API calls and heavy operations with `ErrorService.safecall`.

Logging
- Use `Logger` with category names (e.g., `Logger.new("ItemService")`).
- Levels: DEBUG for development traces, INFO for state changes, WARN for recoverable anomalies, ERROR for rejections.
- Avoid raw `print`; keep logs concise; no spam in tight loops.

Data & Saving
- After profile mutations, call `DataService:QueueSave(player)`.
- For coins/gems, use `CurrencyService.add/canAfford` to ensure totals and to emit currency changed events.
- Inventory changes should emit delta or snapshot via `EventBus` (see `InventoryService`).

UI Guidelines
- Use `BasePanel`, `TabbedPanel`, `BaseChip`, `Theme`, `ThemeRefresher`, `UIUtils`.
- Route opens/closes via `UIManager:showScene/hideScene`; register scenes with unique names.
- Use `Theme.animations` for all tweens; no ad-hoc `TweenInfo` literals.
- Respect safe area; use `ZIndexBehavior.Sibling`; avoid blocking camera controls unnecessarily.

Code Style (Luau)
- `--!strict` at top; type annotations for public functions/records.
- Small, focused modules; single responsibility; no globals.
- Feature flags under `GameConfig.Features` with safe defaults.
- Keep file touched count minimal per PR; update documentation under `coordination/`.

RF & Event Contracts
- RF Result shape: `{ ok: boolean, success: boolean, ... }` (except documented raw maps like GetEquippedItems).
- Validate payloads; cap list sizes; set rate limit (e.g., 0.3–0.5s) to prevent spam.
- Use `Result.lua`/contracts where applicable to normalize responses.

Testing & QA
- Manual Studio tests for happy/edge paths.
- Verify no stuck drops, currency never negative, inventory deltas emitted, and UI toasts display.
- Include short “Test Notes” in PR description.

Module Reuse Pointers
- DI/Services: `server/MiningGame/ServiceContainer.lua`, `ServiceManager.lua`, `SchemaValidators.lua`.
- Events: `shared/MiningGame/EventBus.lua`, `EventNames.lua`, `EventContracts.lua`.
- UI: `client/MiningGame/UI/Components/*`, `shared/MiningGame/UI/*`.
- Econ: `server/MiningGame/CurrencyService.lua`, `server/MiningGame/InventoryService.lua`.
- Loot: `server/MiningGame/LootService.lua`, `shared/MiningGame/CosmeticDefinitions.lua`.
