W1 - Enhanced Cosmetics + Perks (No Model Swaps)

Links: coordination/REORG_2025-09-14.md | coordination/ENGINEERING_STANDARDS.md | coordination/workers/README.md

Decision
- Use server-authored Effects for perks (hardened path). Speed multipliers are quantized to tiers: +5%, +10%, +15%.

Manager Decision (2025-09-14)
- Approach: Use Effects path (CharacterStateManager) for perks. Do not use client-only attributes for gameplay.
- Feature flags: `GameConfig.Features.ENHANCED_COSMETICS_ENABLED = true`, `GameConfig.Features.ENHANCED_PERKS_ENABLED = true` (gate server application; UI may read catalog regardless).
- Stacking policy: Highest `speedMult` wins; `tripleJump` enabled if any equipped item grants it.
- Standards: Use DI (`ServiceValidator.get/tryGet`), `Logger`, and `ErrorService.safecall`; keep diffs focused and typed; no modelSwap work for launch.

Scope
- Keep current generated cosmetics (wings, aura, trails, head, pickaxe skin).
- Add two enhanced perks granted by select cosmetics:
  - Speed Boost (movement speed multiplier)
  - Triple Jump (uses existing DoubleJump system, gated per-player)
- No model swap work this phase.

Perk Flag Schema (proposed, definitions only)
- In `shared/MiningGame/CosmeticDefinitions.lua` item entries, allow an optional `perks` table:
  - `perks = { speedMult = 1.15, tripleJump = true }`
- Visual-only flags continue to live alongside (e.g., `glows`, `animates`, `effect`).

Implementation Plan (no code changes yet; for review)
- Definitions
  - Identify 2–3 cosmetics to mark as enhanced and add `perks` as above.
  - Stacking policy: if multiple enhanced items are equipped, use the highest `speedMult`; enable `tripleJump` if any item grants it.

- Server (W3 – server flags)
  - On equip/unequip in `InventoryService`, compute current effective perks from equipped cosmetics.
  - Apply perks via Effects path (selected):
    - Speed tiers mapped to effect IDs: `cosmetic_speed_105`, `cosmetic_speed_110`, `cosmetic_speed_115` (one applied at a time, longest duration, refreshed on change).
    - Triple jump presence via `cosmetic_triple_jump` effect.

- Client (W1)
  - Speed: No change needed beyond existing aggregator (CharacterStateClient -> ApplyStats picks up movement effects).
  - Triple Jump: Gate by presence of `cosmetic_triple_jump` in CharacterStateClient effects snapshot.

Acceptance Criteria
- Equipping an enhanced cosmetic with `perks.speedMult` increases that player’s movement speed; unequipping restores prior speed.
- Equipping an enhanced cosmetic with `perks.tripleJump` enables triple jump immediately; removing it disables triple jump after landing.
- Works across respawns and two-client sessions; no errors or log spam.
- With multiple enhanced items: speed uses highest multiplier; triple jump enabled if any item grants it.

Interfaces & Events
- Equip/Unequip via `server/MiningGame/RemoteFns/Inventory.rf.lua` (`EquipItem`, `UnequipItem`).
- Broadcasts: `EQUIPMENT_CHANGED` continues to drive client visuals; movement perks applied via server flags/effects as above.

Dependencies
- `GameConfig.Features.COSMETICS_ENABLED` must be true.
- Visual renderers `client/MiningGame/Cosmetics/Renderers/*` unchanged.
- Double Jump: `character/Movement/DoubleJump.client.lua`; Movement aggregator: `character/Movement/ApplyStats.client.lua`.

Risks / Notes
- Keep server authoritative for movement perks; avoid client-only trust for gameplay-affecting changes.
- Minimal, reversible changes; no model swap code touched.

Next Steps
- Confirm which cosmetics are “enhanced” and their `speedMult` values.
- Manager to choose server flag approach: A) effects or B) attributes.
- W1 to prepare a small diff proposal per chosen path for approval (only files named above).
