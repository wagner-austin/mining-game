# W4 — Magnet + forced‑claim; zero orphaned drops

Links: coordination/REORG_2025-09-14.md | coordination/ENGINEERING_STANDARDS.md | coordination/workers/README.md

Objectives
- Reduce or eliminate orphaned loot drops by adding magnet pickup and a forced‑claim safety.

Deliverables
- Magnet behavior: enlarge/periodically pull nearby drops to the player within a tuned radius (respect `AUTO_COLLECT_RANGE`).
- Forced‑claim: on certain lifecycle edges (e.g., player leaving, timed grace expiry), attempt claim/cleanup to prevent orphans.
- Configuration knobs in `GameConfig.Loot` (ranges, timing), guarded by a feature flag.

Interfaces & Events
- Item flow: `server/MiningGame/ItemService.lua` (spawn/collect), `RemoteFns/Item.rf.lua` (`PickupItem`).
- Events: reuse existing inventory/currency events for feedback; optional `NOTIFICATION_PUSH` on mass‑claim.

Dependencies
- Current auto‑collect constants in `GameConfig.Loot` (e.g., `AUTO_COLLECT_RANGE`).
- Coordinate with `SoundManager` for pickup sounds to avoid spam.

Acceptance Criteria
- Standing still near drops pulls them in smoothly; no noticeable perf degradation.
- On session end or elapsed timer, leftover eligible drops are claimed or cleaned safely.
- No double‑claim; inventory updates via deltas; no negative side effects on co‑op scenarios.

Notes
- Keep server authoritative on ownership; magnet should not allow stealing within owner grace.
