# W4 – Magnet + forced-claim; zero orphaned drops

Links: coordination/REORG_2025-09-14.md | coordination/ENGINEERING_STANDARDS.md | coordination/designs/W4_DROPS_RELIABILITY.md | coordination/workers/README.md

Objectives
- Eliminate orphaned loot drops while preserving satisfying pickup visuals.

Status (2025-09-14)
- Implemented owner magnet and forced-claim sweep in ItemService (low-risk, reused bulk add + animations).
- Design doc added: coordination/designs/W4_DROPS_RELIABILITY.md.

Changes Landed
- server(items): owner magnet and forced-claim sweep
  - Owner magnet: dynamic radius grows with age (delay 0.8s; 12 → 35 studs over 3s) for owners even without auto-collect.
  - Forced-claim: ~1 Hz sweep to grant to owner or clean invalid/expired drops.
  - Flags read if present: `Features.LOOT_MAGNET_ENABLED`, `Features.FORCED_CLAIM_ENABLED` (default on if absent).
  - Tuning reads if present: `Loot.MAGNET_START_DELAY`, `MAGNET_START_RANGE`, `MAGNET_MAX_RANGE`, `MAGNET_GROWTH_SECONDS`.

Deliverables
- Owner magnet: after ~0.8s, auto-collect drops if owner enters a growing radius (start ~12 → up to ~30–35 studs), preserving fly-to-player animation.
- Forced-claim fallback: if a drop becomes invalid (no PrimaryPart) or exceeds lifetime/grace thresholds, grant to owner inventory and remove model.
- Optional: ring spawn (`GameConfig.Loot.SPAWN_MODE = "ring"`) if it improves visibility/collection.

Interfaces & Events
- Item flow: `server/MiningGame/ItemService.lua` (spawn/collect), `RemoteFns/Item.rf.lua` (`PickupItem`).
- Events: reuse existing `INVENTORY_DELTA`/`CURRENCY_CHANGED` for feedback.

Config & Flags
- Tune `GameConfig.Loot.PICKUP_RANGE`, `AUTO_COLLECT_RANGE`, `ITEM_LIFETIME`, `DESPAWN_RETRY_DELAY`, `OWNER_GRACE_SECONDS`.
- Optional flags in `GameConfig.Features` (if desired for QA toggles):
  - `LOOT_MAGNET_ENABLED = true`
  - `FORCED_CLAIM_ENABLED = true`

Acceptance Criteria
- Five-minute dig session leaves zero drops behind; pickups feel responsive; no server errors.
- Magnet prioritizes owner within grace; no double-claim; inventory deltas emitted.
- Visuals remain: flyDropToPlayer runs; no regressions.

Next
- Optional: add explicit flags/tuning constants to GameConfig for easier QA toggling.
- Evaluate `SPAWN_MODE = "ring"` only if visibility/collection still needs polish.

Notes
- Keep server authoritative on ownership; do not change loot math; avoid visual regressions.
