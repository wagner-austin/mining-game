Checklist (initial)
- Shop RFs
  - GetShopCatalog: returns items, prices; respects feature flags and filters.
  - PurchaseItem: success (affordable); failures (`INSUFFICIENT_FUNDS`, `ITEM_NOT_FOUND`, `INVALID_INPUT`, flag disabled).
  - Rate limit respected; repeated calls do not double-spend.
- UI
  - Left nav renders; Shop tab respects `SHOW_SHOP_TAB`.
  - Inventory filters behave; Sticky Sell Bar works; cannot sell unsellables.
  - Robux purchase prompts fire (Studio stub acceptable); no crashes.
- Integrity
  - Coins never negative; inventory counts stable; saves queued.
  - Events: `CURRENCY_CHANGED`, `INVENTORY_DELTA` observed on client.
- Flags
  - Toggling flags hides UI and disables RFs with `NOT_AVAILABLE` errors where appropriate.

### W4: Drops Reliability (Magnet + Forced-claim)
- Setup
  - Ensure `Features.LOOT_MAGNET_ENABLED = true`, `Features.FORCED_CLAIM_ENABLED = true`.
  - Tuning defaults: `MAGNET_START_DELAY=0.8`, `MAGNET_START_RANGE=12`, `MAGNET_MAX_RANGE=35`, `MAGNET_GROWTH_SECONDS=3`.
- Owner-first behavior
  - During `OWNER_GRACE_SECONDS`, only owner can pickup via magnet; non-owners must wait.
  - Outside grace, non-owners can collect per existing rules.
- Five-minute session
  - Dig continuously and intermittently; move in/out of magnet range.
  - Expected: zero orphaned drops; no server errors; visuals (fly-to-player) intact.
- Edge checks
  - Invalid drop (delete PrimaryPart) → forced-claim grants to owner and cleans up.
  - Expired drop (ITEM_LIFETIME + DESPAWN_RETRY_DELAY) → grant to owner or despawn; no orphans.
  - Logs are not spammy (no per-frame spam; only initial INFO lines).

Notes
- Record repro steps, expected vs actual, and attach minimal logs (service + RF names, error codes).
